# Shift feasibility assessment (assessment only; nothing implemented)

No shift is recommended on expected RL degradation. Status refers to the pinned upstream commit.

| Candidate | Term / BC affected | Supported mechanism | Initial domains & reference stats | Co-changes | Stability concerns | Validation measurements | Controlled experiment feasible? |
|---|---|---|---|---|---|---|---|
| Re / viscosity | viscous term ν∇²u; ν = U/Re | **Between episodes:** construct a different registered variant (Re 100/250/500, but resolution also changes 24→32). **Arbitrary Re:** needs a custom `make`/ctor with `load_initial_domain=False`, which builds a *fresh* domain (cylinder_env_base.py:247-268) | Domain dir keyed by Re+res; arbitrary Re has **no stored domains and no stats** → `cd_ref` = 0.0 and no uncontrolled reference unless regenerated (compute, ~400+ steps each) | Re 100→250 changes resolution (grid), reward scale, `cd_ref`; env_id `easy→medium` confounds Re with grid | Higher Re may need smaller dt/CFL; 2D flow beyond Re≈ 200-300 is physically 3D, so 2D results are model-level only [domain knowledge, not verified here] | Mean Cd, Cl RMS, St (resolution limits!), vorticity fields, solver sub-step counts | **Partly.** Cleanest design: same resolution, new Re with regenerated domains + stats. Priority questions before choosing: (1) is ν stored per block or per domain, and can a loaded domain's viscosity be reset safely (needs C2-style runtime test); (2) can stats be regenerated for new Re without touching shared data directories; (3) do medium/hard require different dt for stability.
